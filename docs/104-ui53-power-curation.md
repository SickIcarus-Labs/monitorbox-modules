# UI53 / #104 — Power capability normalization and picker curation

> **Historical signed UI49–UI54 design/physical-acceptance milestone.** Version-specific experiments, pending fixes, old release candidates and prior UI composition behavior below are dated evidence, **not** instructions for the currently installed signed UI or the v3 package/update plane. Current authority is the exact installed UI release and its signed module/configuration contract.


Physical operator screenshots on actual Broad Leaf (iPad Safari, 2026-09-26) confirm UI52 v5 Power correctly selects both UPS objects and renders honest current charge/runtime/load/voltage, but expose 27 raw items for Network UPS, including `driver.parameter.pollfreq`, `driver.parameter.pollinterval`, product/vendor IDs, driver version, and NUT shutdown delays.

**Scope:** Power presentation only, within #104; #103 header and all UI52 contracts remain unchanged. Signed UI52 `1.16.0 build52` is immutable. New candidate is UI53 `1.17.0 build53` on a branch stacked on #108. No Core runtime or NUT provider/check/credential mutations.

1. Put the shared, provider-neutral Power presentation adapter in the generic catalog: map reported normalized semantic UPS roles (battery charge %, runtime in minutes/seconds, load %, input voltage) using an optional producer-supplied role map and conservative canonical aliases. Preserve original opaque metric source keys for persisted user selections. No source label / host ID / NUT adapter detection.
2. Native v5 Power card consumes that adapter for each selected member; missing/unreported values remain visibly absent or unknown. Battery/utility status is canonical producer metadata; do not invent or infer from charge/load. Keep member choice and card health exactly as UI52 already does. Apply one unit conversion only when units reported or semantically unambiguous.
3. One shared Add Item picker for builtin/custom/mixed cards: human-readable Recommended UPS readings, separate status, optional additional measurements, and *opt-in Advanced UPS diagnostics/configuration* rather than 27 uncurated flat rows. For a Power card with native member sections, don't offer already-native default readings as additional items except when already saved (never silently drop existing saved items). Searching must not expose hidden diagnostics unless Advanced is explicitly on. Preserve all genuine raw telemetry when Advanced is enabled; no deletion of monitored data.
4. Preserve v1–v4 snapshots, custom cards, all non-Power picker groups and existing saved selections. Upgrading the signed UI52 appliance must NOT regenerate or rewrite its current layout. Use the normal signed dev successor / exact-head release policy after CI; no promotion to beta/stable/main without operator acceptance.

**Required tests:** capability aliases/units/unreported values, driver metadata/config gating, 27-item UPS fixture, custom-card recommendation versus native Power duplicate suppression, selected old raw reference remains available and saved, ordinary search vs Advanced, output HTML screenshot desktop/iPad/mobile, generated-card/Arrange/Reset parity, immutable UI52 package SHA and exact Core 2.7 compatibility.
